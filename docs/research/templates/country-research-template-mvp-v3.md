### 3.N.9. Логика статуса маршрута

Для каждого обязательного условия создать отдельное правило.

| Условие | Поле анкеты | Оператор | Значение маршрута | Статус при выполнении | Статус при невыполнении | Действие пользователя | Текст объяснения |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

Разрешены только:

- `SUITABLE`
- `SUITABLE_WITH_CONDITIONS`
- `UNSUITABLE`

Правила:

- стандартная подготовка документов, период выписок, апостиль, перевод, поездка и место подачи не понижают статус;
- доход ниже обязательного порога всегда даёт `UNSUITABLE`; намерение повысить доход не исследуется;
- длительность занятости, история дохода, срок договора и срок бизнеса не являются вопросами анкеты и не создают `SUITABLE_WITH_CONDITIONS`;
- `SUITABLE_WITH_CONDITIONS` допустим только для создания отсутствующего юридического основания: обязательной оферты, поступления, компании или инвестиционного актива;
- подтверждённое нарушение обязательного требования даёт `UNSUITABLE`;
- критически неполный маршрут получает `publishable: false`;
- индивидуальная проверка описывается текстом, а не отдельным статусом.
